## 1. 근거
- neta.art 픽셀아트 크기 가이드: https://neta.art/explore/guide/pixel-art-sizes?locale=ko
  - 32x32: 요소당 4~6색, 총 12~16색, 3단계 램프, 1px 윤곽은 순흑 대신 어두운 색, 그림자는 재질당 1단계
  - 64x64: 얼굴이 기호가 아닌 얼굴로 읽히는 첫 크기. 눈 8~20칸, 하이라이트 가능, 재질당 3~5단계 램프, 총 16~32색
  - 금속은 색조보다 명도 대비로 표현
  - 표시·내보내기는 정수배, 최근접 이웃 확대
- 기존 디자인 토큰: mockups/source/base.css (Cozy RPG Pixel System)

## 2. 업로드 이미지 기준 품질 수준 (외형 재현 대상 아님)
- 업로드 이미지는 화면 캡처 축소본(89x121)이라 원본 격자 크기 측정 불가. 64x64 등급 상당으로 판단(추정).
- 기준으로 삼는 항목
  - 외곽선: 1px, 어두운 갈색 계열(순흑 아님), 밝은 면은 한 단계 밝은 선
  - 음영: 재질별 3~4단계 램프 (머리·의상·금속 각각)
  - 하이라이트: 머리카락, 눈, 금속 소품에만
  - 소품: 손에 드는 아이템 1개, 명도 대비로 재질 구분
- 서비스 캐릭터의 형태·의상·색 조합은 별도 설계. 해당 캐릭터의 헤어스타일·의상·소품 형태는 사용하지 않음.

## 6. 작화 규칙
- 광원 좌상단 고정 (UI 패널 inset 하이라이트 방향과 동일).
- 외곽선: 실루엣 바깥 #34190C, M 이상 2px·S 1px(v0.5), 밝은 면 안쪽 경계는 #68381E (선택적 외곽선).
- 그림자는 광원 반대(우하단)에 재질당 1단계, 접히는 부위만 2단계.
- 하이라이트(램프 index 0)는 hairBack·hairFront·face·headAcc·prop·fx만 사용.
- 순흑(#000000)·순백 대면적 금지. 순백은 눈·금속 하이라이트 1~2칸만.
- 중간색 안티에일리어싱은 램프 내 색으로만, 외곽선 바깥 금지.
- 색 변형은 `recolor`로 램프 교체 (형태 데이터 재사용).
- 렌더: 정수 배율, `image-rendering: pixelated`, `shape-rendering: crispEdges`.

## 7. 데이터 구조 요약
```ts
CharacterDef { id, name, concept, tier: 'S'|'M', parts: PartAsset[], recolor? }

Ramp        { id, steps: Hex[] (밝음→어두움), role, source: 'token'|'added' }
```

- `renderSVG(char, scale)`: z순 합성, 정수 배율만 허용

## 8. 개념 도식 캐릭터 (v0.2, 2026-11-18)

코드: [diagramCharacter.ts](../src/components/pixel/diagramCharacter.ts)(생성기) · [conceptCharacters.ts](../src/components/pixel/conceptCharacters.ts)(정의)

디자인·캐릭터화 절차 정리본: [concept-diagram-characters.md](concept-diagram-characters.md)

§4의 사람형 파츠 슬롯은 소설 등장인물(인물 노드)에만 쓴다. 개념 노드에서 나온 캐릭터는 아래 원칙을 따른다.

### 8.1 원칙
1. **몸통 = 그 개념의 도식.** 슬라임·동물처럼 개념과 무관한 형태는 쓰지 않는다. 교재·강의에서 그 개념을 설명할 때 실제로 그리는 그림(그래프 궤적, 자료구조 그림, 간트 차트, 상태도 등)을 실루엣으로 삼는다.
2. **도식의 데이터를 바꾸지 않는다.** 꼭짓점 순서·막대 길이 순서·칸 수는 원 도식 그대로 둔다. 예: FCFS는 교재 예제 P1(24)·P2(3)·P3(3)의 간트 차트를 시간 0~30 → x 3~29로 옮긴 블록 3개 + 시간축.
3. **S 등급에서 허용하는 단순화**: 같은 방향으로 이어지는 점 합치기(일직선 위의 점), 축·눈금·라벨 생략, 반복 요소는 4개까지. 단순화해도 2번(순서·대소 관계)은 유지.
4. **얼굴은 도식 위에.** 눈은 도식의 꼭짓점·칸·노드 위에 둔다(FCFS: 가장 긴 P1 블록). 입·홍조는 선택.
5. **팔다리는 도식 가장자리에서.** 외곽선 색 1px 선 + 몸통 램프 손(2x2)·발(4x2). 도식에 원래 있는 요소(화살표, 해시 체인)가 팔다리 역할을 하면 그것을 우선 사용.
6. **강조점**: 원 도식에서 강조한 지점(디스크 스케줄링의 빨간 '현재 헤드' 등)은 강조색(#E0674F) 점으로 남긴다.
8. **책의 맥락을 따른다.** 같은 이름의 개념이 여러 분야에 있으면(FCFS: CPU·디스크 스케줄링) 그 책이 다루는 쪽의 도식을 쓴다.
7. **전용 도식이 없는 개념**(사용자가 추가한 새 콘텐츠 등)은 관계도 노드 도식 `d_node`를 기본형으로 쓰고, 책의 색 계열·실루엣(§13)을 입힌 뒤 노드 id 기준으로 보조 램프만 바꾼다. 배정이 없는 콘텐츠는 중립 기본형.
9. **색 계열·실루엣은 콘텐츠가 정한다(v1.0, §13).** 주 램프 = 콘텐츠 계열 램프, 보조 램프 = 같은 계열 보조 또는 중립. 팔다리·머리 장식은 콘텐츠 실루엣이 붙인다.

### 8.2 작화 (생성기가 자동 처리)
| 항목 | 규칙 |
|---|---|
| 선 도식 | 두께 2px(M 4px). 아래 가장자리 어두움(램프 2), 나머지 중간(램프 1) |
| 면 도식(막대·칸·원·다각형) | 위 가장자리 밝음(램프 0), 아래·오른쪽 가장자리 어두움(램프 2) — 광원 좌상단(§6) |
| 칸 구분 | 1칸 비우면 1px 외곽선이 생겨 칸 경계가 됨 |
| 외곽선 | 8방향 1px, #34190C |
| 눈 | S 3x6 세로 타원(§9.3과 같은 방식). 검은자 50% |
| 색 | 주 램프 1개(a·m·d) + 보조 램프 1개(e·f·g) + 외곽선·흰자·강조·홍조 = 최대 10색 |
| 주 램프 | (v1.0) 콘텐츠 계열 램프(§13.2). 콘텐츠 없는 공용 캐릭터는 중립 램프 |

### 8.3 등급
- (v0.9) 인간형(§10)과 같은 기준: 원본 격자 32x32 1벌만 만들고, 화면에서는 `PixelSprite fit`으로 정수배·최근접 이웃 확대만 함. M·L 등급은 만들지 않음. 스프라이트 이름 `d_<개념>`.
- 외곽선: 실루엣 바깥 1px #34190C, 8방향(인간형과 같음).
- 색: 주·보조 램프 각 3단계 + 외곽선·흰자·눈 파랑·강조·홍조 = 최대 11색. 인간형 상한 16색 이내(현재 6~10색).
- 바둥 프레임(`d_<개념>~flail<n>`): 32x32에서 손 3칸·발 2칸 상하좌우 순환, 눈 > <, 물결 입, 홍조.
- 미리보기: [images/concept-characters-32.png](images/concept-characters-32.png)(6배)

### 8.5 새 개념 캐릭터 추가 절차
1. 그 개념의 대표 도식 1개를 고른다(교재 그림 기준). 수치 예제가 있으면 그 수치를 쓴다.
2. `conceptCharacters.ts`에 `body`(line·rect·disc·ring·poly·clear)와 `rig`(eyes·arms·legs·mouth·markers)를 S 좌표로 추가.
3. 화면에서 32px 원본과 확대 표시(64·96·128px)를 확인. 도식이 뭉치면 3번 단순화 범위 안에서 간격을 넓힌다. 색 수가 16 이하인지 확인.
4. 노드·캐릭터 데이터의 `sprite`에 키를 넣는다.

### 9.1 근거
- 사용자 제공 참고 이미지(기존 게임 캐릭터의 팬아트 픽셀 스프라이트)에서 **해상도·색 수·음영 밀도만** 기준으로 삼음. 인물 디자인·의상·문양은 사용하지 않음(§2와 동일).
- 참고 이미지 측정(추정): 캐릭터 1개 약 90~100px 높이, 1px 짙은 외곽선, 재질별 4~5단 음영, 눈은 홍채 3단 + 하이라이트 2점, 장갑·부츠·금속 버클 같은 소품 재질 구분.
- 픽셀아트 크기 가이드(neta.art, §1)의 64x64 이상 기준(재질당 3~5단 램프, 총 16~32색)을 96x96까지 확장 적용.

### 9.2 등급 표
| 등급 | 캔버스 | 좌표 배율 | 표시(fit) | 색 수(캐릭터당) | 음영 |
|---|---|---|---|---|---|
| S | 32x32 | 1 | fit < 64 (아이콘·작은 목록) | ≤ 10 | 3단 |
| M | 64x64 | 2 | 64 ≤ fit < 96 (관계도 노드, 퀴즈·회상 안내) | 20~30 | 5단 |
| L | 96x96 | 3 | fit ≥ 96 (마을, 탐색 카드·상세, 온보딩) | 20~30 (현재 21~29) | 5단 + 디더링 |

- 정의는 S 좌표 1벌. M·L은 생성기가 좌표를 2·3배로 다시 래스터화(확대가 아님).
- `PixelSprite fit`이 등급을 고름: fit 안에 들어가는 가장 큰 등급(L→M→S), 배율은 정수.

### 9.3 작화 규칙(M·L)
| 항목 | 규칙 |
|---|---|
| 외곽선 | #34190C 2px(1겹째 8방향 + 2겹째 4방향). 캔버스 가장자리 2칸 안에 닿은 부분은 안쪽 2칸을 외곽선색으로 칠함. S는 1px 8방향 |
| 부품 경계 내부선 | 재질(주·보조·팔다리·장갑) 경계 1px #68381E |

| 눈 | 세로로 긴 타원. 흰자 없이 검은 바탕, 위쪽 흰 하이라이트(좌상단 광원), 아래쪽 파란 그라데이션(진함 #1F4F86 → 중간 #3B8FBF → 밝음 #7FC8E8). 검은자(검정 + 진한·중간 파랑) = 외곽선 안쪽 칸의 50~60%: L 8x15(40/76칸 53%), M 5x11(15/27칸 56%), S 3x6(2/4칸 50%). 참고 이미지(기존 게임 캐릭터)에서는 눈 표현 방식만 사용 |
| 입 | L 3줄(웃는 입 + 빨간 안쪽), M 2줄 |
| 홍조 | 얼굴 바깥쪽에만 2단(분홍·진분홍) |
| 강조점 | 원판 3단(밝음·기본·어두움) + 외곽선 |

### 9.4 팔레트(캐릭터당)
- 주 램프 5 + 보조 램프 5 + 팔다리 3~5 + 장갑·부츠 5 + 외곽선 2 + 눈 5(흰자·흰자 그늘·홍채 3) + 홍조 2 + 입·강조 1~3 + 광택 1~2 + 버클 2.
- 실제 사용 색은 도식에 따라 21~29색(시트 라벨에 표시). 32색 초과 금지.
- 관계도에서 전용 도식이 없는 개념은 `conceptVariant('d_node', 램프)`로 주 램프만 바꾼 변형을 등록해 사용.

### 9.5 성능
- `PixelSprite`는 같은 색이 가로로 이어지는 칸을 rect 1개로 합쳐 그림(L 1개당 수천 → 수백 개).


## 10. 인간형 SD 캐릭터 32x32 (v0.6, 2026-11-19)

코드: [humanCharacter.ts](../src/components/pixel/humanCharacter.ts)(생성기) · [humanCharacters.ts](../src/components/pixel/humanCharacters.ts)(정의) · 규격 상수 `HUMAN_SD`·`S_LIMIT` · 미리보기 [images/human-sd-32.png](images/human-sd-32.png)

### 10.1 원칙
- 모든 인간형 캐릭터(소설 등장인물·내 아바타·저자 대표 캐릭터)는 SD(마스코트) 비율 픽셀아트로 그림.
- 원본 격자 32x32 1벌. 화면에서는 정수배·최근접 이웃으로만 확대함(§1 근거). M·L·XL 벌은 만들지 않음.
- 색 수는 §3 S 등급 기준(총 16색 이하, 램프 3단 이하)을 따름.
- 요소 사이를 명도로 분리함. 인접 요소는 기본색 명도 차이를 두고, 경계에 1px 내부선(아래 요소의 그림자색)을 넣음. 같은 명도대 색끼리 맞닿아 장면 전체가 한 평면으로 보이는 것을 막기 위함.

### 10.2 표시 크기(정수배)
| 화면 | fit | 배율 | 표시 크기 |
|---|---|---|---|
| 마을(드래그 포함)·탐색 상세 | 128 | 4배 | 128px |
| 탐색 카드 | 96 | 3배 | 96px |
| 관계도 노드·캐릭터 선택·구매 시트 | 64·88 | 2배 | 64px |
| 상단바·내 정보 아바타·구매 확인 | 34·48·50 | 1배 | 32px |

- 스프라이트 이름 `h_<id>`. 예전 이름 `person`·`hatman`은 각각 `h_reader`·`h_keeper` 별칭(저장 데이터 호환).

### 10.3 SD 체형(32칸)
정의 좌표는 1칸 = 4단위(0~128)로 적음. 아래는 칸 단위.

| 부위 | 위치·크기 |
|---|---|
| 머리 | 중심 (16,11.75), 반지름 7.75x7 → 4~18행, 폭 16칸 |
| 몸통 | 어깨 폭 7.5칸(17행) → 밑단 11칸(25행) |
| 머리 : 몸 | 14 : 12.5 ≒ 1 : 0.9 (2등신) |
| 팔·손 | 어깨 (12.5,18.75)·(19.5,18.75) → 손, 굵기 3칸, 손 지름 3칸 |
| 다리·신발 | 엉덩이 (14,24.75)·(18,24.75) → 발, 굵기 3칸, 신발 5x3칸 |
| 눈 | 2x3칸: 왼쪽 위 흰 하이라이트 1칸, 검정 3칸, 아래 파랑 2칸. 12~14행 |
| 입·홍조 | 입 2칸(16행), 홍조 눈 바깥쪽 아래 2칸씩(15행) |

- 손·발 위치는 포즈 값. 손에 든 소품(등불·편지·지도·책·빵)은 손 좌표 기준으로 그려 손과 함께 움직임.

### 10.4 색 규칙(§3 S 등급)
| 항목 | 기준 |
|---|---|
| 캐릭터 전체 | 16색 이하(투명 제외). 현재 노윤·하람·여행자·독자 16, 로테 15 |
| 요소(재질)당 | 기본 + 그림자 2톤(§1 32x32: 그림자는 재질당 1단계). 램프 정의는 3~5단이고 생성기가 [1, n-2]번째(3단 램프는 [0, 1]번째)를 고름 |
| 공통 고정색 | 외곽선 #34190C, 흰색(눈 하이라이트), 파랑 #3B8FBF(눈 아래), 홍조 #FF9EB5 |
| 넘칠 때 | 생성기(limitColors)가 RGB 거리가 가장 가까운 두 색부터 합침. 같은 요소의 기본·그림자는 거리에 1.6배 가중해 늦게 합침(명암 유지). 고정색은 합치지 않음 |
| 재질 공유 | 재질이 많은 캐릭터는 램프를 공유해 색 수를 줄임(예: 노윤 머리카락·바지 = 같은 갈색 램프) |
| 명도 분리 | 맞닿는 요소의 기본색은 명도 차이를 둠(예: 크림 목도리 ↔ 남색 코트, 밝은 피부 ↔ 짙은 머리) |

### 10.5 작화 규칙
| 항목 | 규칙 |
|---|---|
| 외곽선 | 실루엣 바깥 1px #34190C, 8방향. 4배 표시 때 화면 4px로, 개념 캐릭터 L 등급 2px 외곽선(화면 2px)보다 굵게 보임. 32칸에서 2px면 얼굴·손이 묻혀 1px 유지 |

- 프레임 이름 `h_<id>~flail<n>`, 처음 요청 때 32x32로 생성·등록.

### 10.8 새 인간형 캐릭터 추가 절차
1. humanCharacters.ts에 `sdBody(pose, { back, pants, shoes, top, torsoDetail, held, neck, front })`로 정의 추가하고 `content`(콘텐츠 id)를 적음. 주 의상 램프는 그 콘텐츠 계열 램프, 나머지는 같은 계열 또는 공용 중립(§13.3). 재질이 8개를 넘으면 램프 공유.
   실루엣은 그 콘텐츠의 실루엣 유형(§13.4)을 따름. 새 콘텐츠면 다른 콘텐츠와 겹치지 않는 머리 장식·몸통 외곽 유형을 새로 정함.
2. 손 소품은 `p.hands` 기준 좌표로 그림(바둥거림 때 따라 움직이게).
3. `HUMAN_CHARACTERS`에 넣으면 32x32 원본과 바둥 프레임이 자동 등록됨.
4. 미리보기 시트로 전체 색 수(16 이하)와 요소 간 명도 분리 확인.

| 확대 | 정수배만. 인간형·개념 도식 모두 32x32 → 6배(192)(v0.9). 확대 후 192 × 192가 셀 너비에 맞음 |

### 11.2 배치 순서(왼쪽 위부터 행 우선)
1. 인간형: 캐릭터마다 대기 1칸 + 바둥 프레임 4칸(노윤 → 하람 → 여행자 → 독자 → 로테). 0~24번 칸
2. 개념 도식: 대기 1칸씩(conceptCharacters.ts 순서). 25~46번 칸
3. 47~71번 칸: 빈 칸(새 캐릭터용). 72칸을 넘으면 생성 스크립트가 오류를 냄

- 칸 위치는 characters.json(Aseprite JSON Hash 형식, §12.9)의 `frames[이름].frame = { x, y, w, h }`로 조회. 프레임 이름은 `<key>~idle0`, `<key>~flail<n>`. 동작 범위는 `meta.frameTags`.

### 11.3 생성·사용
- `npm run atlas`: 현재 스프라이트 정의로 PNG·JSON을 다시 만듦. 캐릭터를 추가·수정하면 다시 실행해 커밋.
- 앱 화면은 지금처럼 `PixelSprite`(SVG)로 그림. 아틀라스 셀은 6배로 확대돼 있어 화면 크기(32·64·96·128px)로 줄이면 정수배가 깨지기 때문임. 아틀라스는 백엔드 이미지 파이프라인·외부 도구와 주고받는 공통 형식으로 씀.
- 화면에 셀을 직접 쓸 때는 셀 원본 크기(192 × 208) 또는 1/2(96 × 104, 3배)만 사용.

## 13. 콘텐츠별 구별 규칙 (v1.0, 2026-11-20)

코드: [contentStyles.ts](../src/components/pixel/contentStyles.ts)(배정표·실루엣 적용) · 검사 [scripts/check-characters.mjs](../scripts/check-characters.mjs)(`npm run check:chars`)

목적: 마을·관계도에 여러 책의 캐릭터가 섞여도 **어느 책의 캐릭터인지 실루엣과 색만으로 구별**되게 함. 32x32·16색 이하·1px `#34190C` 외곽선 규격(§8.3, §10)은 그대로 둠.

![콘텐츠별 구별화: 변경 전(위) / 변경 후(아래), 아래는 배정표](https://github.com/Waterrrrrit/intereading_2026_bootcamp_hackathon/blob/5ec3070/docs/images/content-distinct.png)

### 13.1 원칙
1. 콘텐츠(책·스토어 콘텐츠) 1개 = **색 계열 1개 + 실루엣 유형 1개**. 두 콘텐츠가 같은 계열이나 같은 실루엣 유형을 쓰지 않음.
2. 같은 콘텐츠의 캐릭터는 계열 색과 실루엣 유형을 공유하고, **도식 모양(개념형)·소품과 의상 배치(인간형)·보조 램프**로 개별 구분함.
3. 다른 콘텐츠의 계열 색은 작은 소품·강조에도 쓰지 않음. 예외는 모든 캐릭터 공통 얼굴색(외곽선·흰자·눈 파랑·홍조·입)뿐.
4. 콘텐츠가 없는 공용 캐릭터(`h_reader` 내 아바타, `d_node` 기본형)는 중립색만 씀.

### 13.2 색 계열
| 항목 | 규칙 |
|---|---|
| 계열 간격 | 계열 램프 중간색(steps[1])의 색상(HSV H)끼리 **30° 이상** 차이 |
| 금지 대역 | H 15~55°는 피부·자연 머리색·가죽·금속 소품이 쓰는 공용 중립 대역이라 계열로 배정하지 않음(배정하면 사람 피부·머리와 구별 안 됨) |
| 주 램프 | 개념형 `ramp` = 계열 램프. 인간형은 면적이 가장 큰 의상(상의·망토·드레스) = 계열 램프. 계열 색 40칸 이상 |
| 보조 램프 | 같은 계열 보조 램프(`companions`) 또는 중립 램프(`clothParch`·`stone`·`leather`) |
| 공용 중립 | 크림·종이(`clothParch`), 회갈(`stone`), 가죽, 피부·자연 머리색, 금·불빛(소품) |

### 13.4 실루엣 유형
개념 도식 캐릭터는 정의 좌표(`body`)를 도식 원형으로 두고, 등록 때 `applyContentStyle`이 콘텐츠 실루엣을 입힘.
1. 몸통 도식 전체를 실루엣 상자(`box`)에 가로·세로 따로 맞춰 늘이고 줄임. 1칸 칸 구분선은 1칸 유지, 원·고리는 타원이 됨, 고리 두께는 짧은 축 비율로 줄임(1칸 이상)
2. 눈·입·강조점은 같은 비율로 옮김
3. 정의의 팔다리는 버리고 실루엣의 머리 장식(줄기·지붕)·팔·다리를 붙임. 다리·팔 시작점은 몸통 모양을 보고 자동으로 찾음(다리: 발 위 열의 가장 아래 몸통 칸, 팔: `fromY` 행의 가장자리 몸통 칸)

| 유형 | 몸통 상자(S 좌표) | 머리 장식 | 팔 | 다리 |
|---|---|---|---|---|
| 단말기형 | x 2~29, y 9~22 (가로 28 × 세로 14) | 가운데 안테나 줄기 + 공(보조 램프) | 없음 | 4개, 1칸 핀 + 3x2 네모 발(보조 램프), 발 y 28 |
| 신전형 | x 8~23, y 9~24 (가로 16 × 세로 16) | 삼각 지붕(페디먼트, y 1~7, 보조 램프) | 2개, 몸통 옆에서 지붕 처마로 올려 받침 | 2개, 2칸 기둥 + 5x2 받침(보조 램프), 발 y 29 |
| 다두형 | x 6~25, y 10~25 | 줄기 3개 끝에 둥근 머리 3개(보조 램프) | 2개, 옆으로 올림 | 2개, 1px 선 + 4x2 발 |
| 현수형 | 정의 좌표 그대로 | 없음 | 정의대로 | 체인 노드가 다리 |

인간형은 공통 SD 체형(§10.3)을 유지하고 머리 장식·몸통 외곽으로 유형을 나눔.

| 유형 | 머리 | 몸통 외곽 |
|---|---|---|
| 모자형 | 모자 꼭대기(방울·높은 제모 크라운)가 머리 위로 솟음 | 허리까지 일자 |
| A라인형 | 올림머리(번)가 머리 위로 솟음 | 아래로 넓게 퍼지는 삼각형 |
| 망토형 | 후드가 머리를 감쌈 | 배낭·망토가 어깨 뒤로 넓게 퍼짐 |
| 기본형(공용) | 맨머리 단발 | 기본 |

### 13.5 관계도 기본 노드
전용 도식이 없는 개념 노드는 `contentVariant('d_node', 책 id, 노드 id 해시)`로 그 책의 계열·실루엣을 입힌 `d_node`를 씀. 노드마다 보조 램프(계열 보조 → 중립 순)만 바뀜. 배정이 없는 책(사용자 업로드 등)은 중립 `d_node`.

### 13.6 새 콘텐츠·새 캐릭터 추가 절차
1. 새 콘텐츠면 `contentStyles.ts`의 `CONTENT_STYLES`에 항목 추가: 아직 안 쓴 색 계열(§13.2 간격·금지 대역 지킴, 램프는 `characterSpec.ts` RAMPS에 `fam<이름>`으로 추가)과 아직 안 쓴 실루엣 유형
2. 캐릭터 정의에 `content`를 적고, 주 램프 = 계열 램프, 보조 = 계열 보조·중립
3. `npm run check:chars` 통과 확인(계열 간격·금지 대역·실루엣 중복·램프 소속·인간형 색 대역·16색)
4. `npm run atlas`로 아틀라스 갱신, 이 절 배정표에 한 줄 추가
5. 배정 가능한 색 계열이 남지 않으면(30° 간격) 새 콘텐츠는 중립 기본형으로 두고 실루엣 유형만 새로 배정
